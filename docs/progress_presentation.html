3 · Accuracy Paradox

ทำไมเราไม่ใช้ Accuracy ตัดสินโมเดล

โมเดลที่ทายว่า “Normal” ทุกกรณี

97.07%

Accuracy ดูสูง แต่…

Recall = 0%

ความผิดปกติ 16,838 ครั้งหลุดรอดทั้งหมด เหมือน IDS ที่ไม่เคยแจ้งเตือน

เกณฑ์ที่ใช้ (ตามที่เรียนเรื่อง Evaluation Metrics)

Recall = TP / (TP + FN) — เกิดเหตุจริง 100 ครั้ง จับได้กี่ครั้ง (กันการหลุดรอด)

Precision = TP / (TP + FP) — เตือน 100 ครั้ง เป็นเหตุจริงกี่ครั้ง (ลด Alert Fatigue)

F1-Score (ตัวชี้วัดหลัก) — Harmonic Mean ของ Precision และ Recall

PR-AUC — วัดทุก Threshold เหมาะกับข้อมูลไม่สมดุลกว่า ROC-AUC เพราะไม่ถูก True Negative จำนวนมหาศาลดันให้ดูดี

4 · Sessionization & Data Split

รวมกลุ่มตาม block_id และแบ่งข้อมูลอย่างปลอดภัย

1. รวมกลุ่มตาม Session (block_id)

  • ในระบบกระจาย เหตุการณ์ของบล็อกเดียวกันกระจายสลับกับบล็อกอื่น

  • ไม่ตัดกลาง Session → ป้องกัน Data Leakage (โมเดลเห็นข้อสอบตอนเรียน)
  • Stratified → คงสัดส่วน Anomaly 2.93% ในทุกชุด

7 · DeepLog (Du et al., ACM CCS 2017)

เรียนรู้จาก Log ปกติล้วน (Normal Only)

ปัญหาที่ต้องการแก้

ในงานจริง ความผิดปกติใหม่ ๆ ไม่มี Label โมเดลจึงควรเรียนจาก Log ปกติเท่านั้น

เทียบกับ SOC

คล้าย Behavioral Baseline ของ UEBA: เรียนว่า “ปกติ” หน้าตาอย่างไร อะไรที่หลุดจากนั้นคือสิ่งที่ต้องตรวจ

🛠️ เทคนิคที่ใช้

  • Sliding Window (h = 10): ตัด Session ปกติเป็นหน้าต่างละ 10 Event ให้ทาย Event ถัดไป (488,673 Windows)
  • Next-Event Prediction = Multi-class Classification: LSTM (Embedding 32, Hidden 64, 2 ชั้น) → Linear → Softmax 47 คลาส · CrossEntropyLoss
  • Top-k Detection: Event จริงไม่อยู่ใน k อันดับที่ทาย → Abnormal Step; Session ที่มี Abnormal Step ≥ 1 → Anomaly
  • เลือก k บน Validation: ทดลอง k ∈ {1,2,3,5,7,9,12,15} ได้ k = 5 (Validation F1 67.12%)
Window = [E1, E2, E1, E1, E3, E3, E4, E4, E3, E4] → LSTM → Top-5  ·  Event จริงถัดไป = E5
E5 ∈ Top-5 → ปกติ  |  E5 ∉ Top-5 → Abnormal Step

DeepLog: ฟังก์ชันและเหตุผล

ฟังก์ชัน / วิธีการใช้ทำอะไรทำไมเลือกใช้
train_raw[Label == 0] · .sample(n=25000, random_state=42)เลือกเฉพาะ Normal Session มาฝึกDeepLog เรียนรู้เฉพาะ “ความปกติ” · สุ่มย่อยเพราะรอบนี้รันบน CPU
extract_sliding_windows(window_size=10) (เติม PAD ข้างหน้า)สร้างคู่ 10 Event → Event ถัดไป ได้ 488,673 Windowsเติม PAD ข้างหน้าทำให้ทายได้ตั้งแต่ Event แรกของ Session
nn.LSTM → lstm_out[:, -1, :] → nn.Linear(64, 47)ให้คะแนน (Logits) กับทุก Event ใน Vocabularyใช้สถานะหลังอ่านครบ Window เป็นบริบทในการทาย

torch.topk(logits, k) + (topk == target).any()เช็กว่า Event จริงอยู่ใน k อันดับแรกหรือไม่ระบบปกติไปต่อได้หลายทาง จึงยอมรับหลายคำตอบแทนการต้องทายถูกเป๊ะ
np.bincount + error_threshold=1นับ Abnormal Step ต่อ Session → ≥ 1 = Anomalyตามกฎตัดสินของ DeepLog

8 · สิ่งที่เราเรียนรู้

Supervised ผ่านเป้าแล้ว — โจทย์ต่อไปคือจับสิ่งที่ไม่เคยเห็น

ข้อมูลไม่สมดุลต้องจัดการทุกขั้น

Stratified Split → Class Weight / pos_weight → Threshold Tuning → วัดด้วย F1 / PR-AUC

Validation Set สำคัญ

ทุกการตัดสินใจ (Threshold 0.95, k = 5) เลือกบน Validation เพื่อให้ผลบน Test เชื่อถือได้

Supervised ≈ Signature-based

แม่นมากกับรูปแบบที่มีตัวอย่าง แต่ต้องพึ่ง Label

Normal-only ≈ Anomaly-based IDS

ไม่ต้องมี Label ของการโจมตี แต่ยากกว่าและยังต้องปรับปรุง

บน HDFS โมเดลเรียบง่ายก็ได้ผลสูง — Deep Learning จึงต้องพิสูจน์คุณค่าด้านอื่นด้วย เช่น การอธิบายผล (Explainability) และการใช้ข้ามระบบ (Generalization)
